# AI驱动需求管理与研发协作平台 - PRD

## 问题陈述

**谁在什么场景下遇到了什么痛点？**

中小研发团队（5-20人）和独立开发者在管理项目需求时面临三重困境：

1. **云端竞品的数据隐私担忧**：Jira、ClickUp、Linear等主流工具均为云优先或纯SaaS模式，用户的敏感情报（产品规划、商业策略、未发布功能）必须上传至第三方服务器。金融、医疗、政府、军工等行业用户对此有强烈的合规要求，但市场上缺乏真正"本地优先"的研发协作工具。

2. **订阅费压力与功能冗余**：按人月收费的SaaS模式对小型团队造成持续成本压力。一个10人团队使用Jira Premium需支付$80/月（约$960/年），而功能却远超团队实际需求。同时，Jira的学习曲线陡峭，配置工作流需要专职管理员，小团队难以负担。

3. **AI能力碎片化**：竞品的AI功能多为附加模块（如ClickUp Brain、Notion AI），仅能完成简单的文本生成和总结，无法深度融入需求管理的工作流。用户需要一个将AI作为核心能力的工具，而非"锦上添花"。

**现在怎么解决的？**

- 使用云端SaaS工具（Jira、Linear、ClickUp）→ 数据外泄风险+订阅费+学习成本
- 使用Excel/Notion自建系统 → 无AI辅助、无协作效率、维护成本高
- 放弃工具直接手动管理 → 人效低下、信息分散、易遗漏

**为什么不行？**

云端方案无法满足数据主权要求；自建方案缺乏AI能力和协作机制；手动管理无法支撑规模化。

## 我们的差异化

**用户为什么选我们而不是竞品？**

1. **数据主权**：所有数据存储在本地SQLite数据库，永不上传云端。满足金融、医疗、政府行业的合规要求。

2. **零订阅费**：一次性部署，永久使用。无按人月收费压力，无版本升级费用。

3. **AI作为核心能力**：不是附加功能，而是深度集成到需求管理的工作流中。AI辅助优化项目描述、生成结构化需求文档。

4. **开箱即用**：单一服务架构（FastAPI + SQLite），零运维成本。无需配置工作流、无需专职管理员。

5. **灵活AI模型配置**：支持OpenAI API、Ollama本地模型、自定义模型端点。用户可选择云端或本地AI，兼顾便利性与隐私。

## 验收标准（Given/When/Then）

### 功能1：项目CRUD

- Given 用户已打开应用，When 用户点击"新建项目"按钮并填写项目名称、描述、状态，Then 系统创建项目并在项目列表中显示
- Given 项目中存在数据，When 用户点击项目卡片，Then 系统展示项目详情（名称、描述、状态、创建时间）
- Given 用户已打开项目详情页，When 用户修改项目名称并保存，Then 系统更新项目信息并显示成功提示
- Given 项目中存在数据，When 用户点击删除按钮并确认，Then 项目被删除且列表刷新

### 功能2：AI辅助优化项目描述

- Given 用户已填写项目描述草稿，When 用户点击"AI优化"按钮，Then 系统调用配置的AI模型并展示优化后的描述
- Given AI已优化项目描述，When 用户点击"应用优化"，Then 系统保存优化后的描述到项目
- Given AI模型未配置，When 用户点击"AI优化"，Then 系统提示用户先配置AI模型
- Given AI调用失败，When 系统收到错误响应，Then 系统显示错误提示并保留原始描述

### 功能3：项目搜索与筛选

- Given 项目列表中存在多个项目，When 用户在搜索框输入关键词，Then 系统实时过滤显示匹配项目
- Given 项目列表中存在多个项目，When 用户选择"状态"筛选器并选择"进行中"，Then 系统只显示状态为"进行中"的项目
- Given 搜索条件和筛选条件同时设置，When 用户清除搜索框，Then 系统恢复显示所有项目（仍应用筛选条件）

### 功能4：AI模型配置

- Given 用户进入设置页面，When 用户填写API端点、API密钥、模型名称并保存，Then 系统保存配置并显示成功提示
- Given 已保存AI模型配置，When 用户测试连接，Then 系统验证配置有效性并显示结果
- Given 配置无效，When 用户保存，Then 系统显示错误提示并要求修正

## 边界条件

### 空状态

- 无项目时显示引导页面："还没有项目，点击创建你的第一个项目" + "新建项目"按钮
- 搜索无结果时显示："未找到匹配项目，尝试调整搜索关键词"

### 错误状态

- AI调用失败时：显示错误提示 + "重试"按钮，保留原始输入
- 网络连接失败时：显示"网络异常，请检查连接"提示
- 表单验证失败时：字段级错误提示（如"项目名称不能为空"）

### 加载状态

- 项目列表加载时：显示骨架屏或Loading spinner
- AI优化请求时：显示"AI正在优化中..."状态，禁用提交按钮

### 边界值

- 项目描述：最大长度10000字符
- 项目名称：最大长度100字符
- 搜索关键词：最大长度50字符
- AI API超时：30秒

### 并发

- 单用户场景，不涉及并发冲突
- 如需多用户，需考虑SQLite写入锁（MVP暂不支持）

### 离线

- 核心功能离线可用（项目CRUD、搜索筛选）
- AI功能需网络连接（MVP阶段）

### 权限

- 单机工具，无权限控制（MVP阶段）
- 后续可考虑本地登录（密码保护）

## 数据埋点方案

### MVP必埋事件

| 事件类别 | 必埋事件 | 说明 |
|----------|----------|------|
| 激活 | project_created | 用户创建第一个项目（产品假设验证） |
| 激活 | ai_optimization_used | 用户使用AI优化功能（核心功能采用率） |
| 留存 | session_start | 用户启动应用（DAU/MAU计算） |
| 留存 | project_viewed | 用户查看项目详情（功能使用深度） |
| 转化 | ai_model_configured | 用户配置AI模型（功能启用） |
| 异常 | ai_api_error | AI调用失败（稳定性监控） |
| 异常 | app_error | 应用错误（用户体验监控） |

### 埋点实现要求

- 前端：使用轻量级`trackEvent()`封装，事件名采用`{对象}_{动作}`格式
- 属性规范：每个事件附带`timestamp`、`device_type`（macOS/Windows/Linux）
- 隐私保护：不上报用户输入内容、不采集API密钥、不采集IP地址
- 存储：本地SQLite记录埋点数据，可选定期导出（MVP阶段可选）
