# 阶段1 问题与优化分析（基于当前代码实态）

> 分析对象：`会议系统/server.py`、`会议系统/agent_sim.py`、`会议系统/agent_skill.md`
> 当前阶段1 已覆盖 AC-1~7（接入/双向/单房间/不调LLM/进入提示/上线状态/结束双触发），并修复了"GET 无 ok 字段导致 agent 永不回复"根因。
> 本文只做**问题定位 + 优化建议**，不改代码。分级：P0=多 agent/真上线前必修；P1=上线调试前建议修；P2=体验/可观测/阶段2 衔接。

---

## 一、P0 必修（多 agent 联调或真上线前会爆）

| # | 问题 | 代码位置 | 影响 | 建议 |
|---|---|---|---|---|
| P0-1 | **多 agent 抢答风暴** | `agent_sim.py:54-55` `mentioned_me`：无 @ 且无 @字样 → 返回 True | 一旦接 ≥2 个 agent，老板发一条普通消息（如"大家好"）会触发**所有 agent 同时回复**，形成刷屏 | 改为：被 @我 / @所有人 才回；无 @ 时**仅当房间里只有我一个 agent** 才回（需从 poll 的 members 判断 agent 数量）。协议 `agent_skill.md` 同步明确"多 agent 房间必须显式 @，普通消息不触发" |
| P0-2 | **结束关键词是精确全等匹配** | `server.py:209` `content.strip() in END_KEYWORDS` | "结束会议吧""我们结束会议""结束会议。"都**不会**结束，只有纯"结束会议"才触发 | 改为子串/归一化匹配：`any(kw in content for kw in END_KEYWORDS)` 或先去掉标点再比对；`END_KEYWORDS` 默认 `{"结束会议","结束","stop"}` |
| P0-3 | **@提及只认 ASCII（`[\w-]+`）** | `server.py:57` `MENTION_RE = @([\w-]+)` | agent 显示名含中文/空格/括号（如"OpenClaw(模拟)"）时，`@名` 无法被解析进 `mentions` → agent 永远收不到"被 @"，等于又回到"@他不理我" | 根因方案：**用 uid 做提及标识**，而非显示名。下拉框 value 存 uid（如 `agent-openclaw`），发送时拼 `@agent-openclaw`；或 join 时强制 name 为 mention-safe 并校验。协议层把"身份=uid"写死 |

## 二、P1 建议修（上线调试体验相关）

| # | 问题 | 代码位置 | 影响 | 建议 |
|---|---|---|---|---|
| P1-1 | **会议结束后无法重置** | 路由无 reset；`phase=done` 后只能杀端口重启（实踩坑） | 调试时一结束就得手动 `Stop-Process` + 重启，反复摩擦 | 加 `POST /api/room/<id>/reset`（boss 身份可调用）：清空 messages、phase 回 `waiting`；或网页加"重新开始"按钮 |
| P1-2 | **boss 身份靠前端硬编码** | `server.py:351` `if (myName === "老板") myUid = "boss"` | 任何人输入"老板"即获 boss 权；身份是客户端自报，服务端不校验 | G4（本机/内网/无鉴权）下可接受，但需**明示风险**；未来应服务端签发 token。当前阶段1 不阻塞 |
| P1-3 | **内存态、无持久化、崩溃即丢** | `rooms = {}` 模块级字典 | "上线调试"若进程崩/重启，房间与全部对话丢失 | 加可选 JSON 落盘（每条消息 append 到 `rooms/<id>/session.json`，启动可重载）；或至少定时快照。阶段1 调试可接受，真上线前必修 |
| P1-4 | **host 0.0.0.0 硬编码 + 无 env 配置** | `server.py:546` `host="0.0.0.0", port=5000` | 0.0.0.0 在共享网络下无鉴权暴露风险；端口/超时不可配 | host/port/`ONLINE_TIMEOUT`/`END_KEYWORDS`/`POLL` 全部走环境变量（默认 127.0.0.1 更安全）；含 0.0.0.0 时打印警告 |
| P1-5 | **agent/人类 角色未区分** | `join` 仅 `uid/name`，无 `role` | 下拉框把**其他人类成员**也列成可选"agent"，老板可能误 @ 真人 | join 加 `role: agent\|human`；下拉框只列 `role=agent` 的成员 |

## 三、P2 体验 / 可观测 / 阶段2 衔接

| # | 问题 | 代码位置 | 影响 | 建议 |
|---|---|---|---|---|
| P2-1 | **done 后输入未禁用** | `server.py` JS 无 `phase===done` 阻断 | 结束后仍可发消息（hint 仅提示"已结束"） | done 时禁用 `#input/#send/#endbtn` 并置灰 |
| P2-2 | **服务端零日志** | `server.py` 仅启动 banner | 上线调试看不到谁加入/发了什么/phase 变更 | 加 `logging` 到 stderr+文件；加 `GET /health` 探活 |
| P2-3 | **房间名硬编码** | `server.py:342` `var roomId = "meeting"` | 无法开多个并行会话 | 从 URL `?room=xxx` 读取；server 已支持任意 room_id |
| P2-4 | **agent 退出无优雅离开消息** | `agent_sim.py` 直接 `break/return` | boss 要等 30s 超时（灰点）才知道它走了 | agent 停止前发一条 `type=system`/普通"已停止"消息 |
| P2-5 | **≤100 字计数含 @前缀** | `agent_sim.py:43` `content[:100]` | 前缀 `@老板 ` 占字数，正文实际更短 | 协议明确"100 字指整条含前缀"或改为"正文≤100"二选一 |
| P2-6 | **阶段2 合并未挂接** | `phase=done` 仅插停止信号，无后续 | D-S1 设计合并留后；但目前 done 后什么都不会发生 | 阶段2：done 时由 merge-agent 读全量 messages 产出共识文档；需确保 P1-3 持久化已就位 |

## 四、结论与推荐下一步

**阶段1 核心链路已通**，可作为"老板 + 1 个外部 agent"的最小闭环 demo 使用（含下拉框 @、3s 轮询、≤100 字、结束双触发）。

**开干前的必做 3 项（P0）**：①多 agent 抢答门控 ②结束关键词子串匹配 ③@用 uid 而非中文名。这三项不修，一旦接第二个工具就会出明显 bug。

**上线调试前建议（P1）**：重置会议、JSON 落盘、env 配置、agent 角色区分。
