# 会议系统 · 阶段1 需求简报（MVP 切片 · B 角色收口）

> 状态：B 角色 `requirement-clarifier` v1.1 收口产出（ready）
> 日期：2026-08-16
> 定位：会议系统全量需求的「第一阶段最小切片」，仅供阶段1 开发/调试使用；合并、多 agent 互评、裁决等留后续阶段。

---

## 1. 背景与真实意图
会议系统旨在让老板与多个**外部 AI 工具**（trae / opencode / openclaw 等）通过"会议"形式协作产出方案。
本轮聚焦**阶段1：先上线调试**，验证最小链路——「外部 AI 工具经 skill 接入平台 → 网页群聊 → 老板结束即停」——能否跑通。后续阶段（多 agent 互评 / 方案合并 / 分歧裁决）**不在阶段1 范围**。

## 2. 范围边界
**做（阶段1）：**
- 外部 AI 工具经会议系统 `agent_skill.md` 接入平台
- 网页聊天室（老板 + 接入 agent 同处一个房间群聊）
- 双向消息流通（老板 ↔ agent）
- 成员**上线状态显示** + **进入聊天室系统提示**
- 「#结束会议」双触发（网页按钮 + 文本关键词 `#结束会议`）→ 接入 agent 停止回复
- 「重新开会」重置（网页按钮）→ 清空消息、phase 回 waiting，已接入 agent 自动恢复、可立即再聊
- 平台**只做消息中转**，不调用任何 LLM（回复完全来自外部工具）

**不做（留后续阶段）：**
- 多 agent 并发互评 / 方案合并 / 分歧裁决界面 / 打分确认
- 多房间 / 多会议并发
- 鉴权（沿用 G4：仅本机 / 内网，绝不上公网）

## 3. 硬约束
- **agent 实体 = 外部 AI 工具**（trae / opencode / openclaw 等），经 skill 接入；**不是自研 Python 客户端**
- 平台技术栈 = Flask（沿用 v1.2 设计文档）
- 部署 = 仅本机 / 内网，无鉴权（G4 决策）
- 平台**不提供 LLM**，agent 的"智能"由外部工具自带

## 4. 验收标准（AC-1 ~ AC-7）
| # | 验收条件 |
|---|---|
| **AC-1 接入成功** | 外部工具加载 skill 后成功连入平台、被标记在线、出现在成员列表 |
| **AC-2 双向聊天** | 老板在网页发消息 → 接入的 agent 收到并回复 → 回复显示在网页消息流（双向流通） |
| **AC-3 结束即停** | 老板点「结束会议」按钮 **或** 发文本"#结束会议" → 平台广播停止信号 → 该 agent 停止回复（≤3s 内）|
| **AC-4 单房间群聊** | 阶段1 为单房间，老板 + 接入 agent 同室；多 agent 架构预留、仅验证 1 个 |
| **AC-5 平台不调 LLM** | 平台本身不调用任何 LLM，回复完全来自外部工具（验证"只中转"） |
| **AC-6 上线状态** | 成员列表实时显示每个接入 agent 的在线 / 离线状态，状态变化有明确视觉标识（如绿点 / 灰点） |
| **AC-7 进入聊天室提示** | 有新 agent 接入 / 进入聊天室时，网页消息流插入系统提示「XXX 已进入聊天室」，老板可见 |
| **AC-8 重置会议** | 老板点「重新开会」→ 消息清空、phase 回 waiting；已接入 agent 自动恢复（保留连接、无需重启），可立即再聊 |

## 9. 方向建议候选集（B 主动补全 · 待老板拍板）
- **关于外部工具接入协议**：建议 `agent_skill.md` 抽象为**通用 HTTP / WS 协议 + 各工具薄适配层**（trae / opencode / openclaw 各一个适配），而非为每个工具写独立 skill。理由：降低维护成本、新增工具只加适配层。是否采纳待老板拍板。
- **关于「结束会议」广播范围**：建议阶段1 单房间场景下，结束信号仅通知当前房间所有接入 agent；多房间预留时按 room 隔离。

## 10. 阶段1 最终行为规范（已固化 · P0 + P1-1）
以下行为已写入代码并实弹验证，作为阶段1 的"硬规则"：
1. **@严格门控**：agent 仅当被 `@自己` 或 `@所有人` 才回复；普通消息（无 @）不触发，根治多 agent 抢答。
2. **结束关键词固定 `#结束会议`**：5 字符精确匹配；旧 `结束会议` / `/结束会议` 不再生效。按钮与该文本一致。
3. **网页自动 boss**：进网页即老板身份、无需输入名字（G4 本机/内网无鉴权；风险：客户端自报 uid，未来应签发 token）。
4. **3 秒轮询 + 心跳保活**：agent 每 3 秒轮询，轮询即心跳；在线 30s 超时判定，绿点/灰点实时。
5. **回复 ≤100 字**：单条回复硬截断 100 字（含 @前缀），须基于用户消息内容。
6. **下拉框选 agent = @**：选中即自动补 `@agent名`，等同于手动 @。
7. **上线状态（AC-6）**：成员列表绿/灰点显示在线/离线。
8. **重置会议（AC-8）**：点「重新开会」清空消息、phase 回 waiting；已接入 agent 保留连接、自动恢复，无需重启即可再聊。
9. **结束即停**：`#结束会议` → phase=done + 停止信号 → agent 停止回复（保留连接待重置）。

## 11. 下一步与阶段2 预览（需求完善 · 待拍板）
阶段1 闭环已成（单 agent + 网页 + 重置）。后续可推进：
- **【进行中】真实 openclaw 接入验证（D-S3 验收终点）**：已产出 `docs/openclaw_接入指令书.md`（复制即用版，工具视角直白指令），把该文件作为指令喂给真实 openclaw，跑通最小闭环、替代模拟 agent。这是阶段1 的"真验收"。
- **【近期】文件持久化（P1-3，老板说"后续"）**：进程重启/崩溃不丢房间与对话 → JSON 落盘 + 启动重载。阶段1 调试可接受内存态，真上线前必修。
- **【中】多 agent 联调**：接入 ≥2 个工具，验证 @门控不抢答、下拉框只列 agent。
- **【阶段2】合并逻辑**：`phase=done` 后由 merge-agent 读全量 messages 产出共识文档（需先有持久化）。
- **【阶段2】多房间/多会议并发**：房间名当前硬编码 `meeting`，可由 URL `?room=` 指定。
- **【安全】端口/env 配置（P1-4，老板说"不急"）**：`host/port/ONLINE_TIMEOUT/END_KEYWORDS` 走环境变量，默认 127.0.0.1 更安全。
