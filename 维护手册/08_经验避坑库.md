# 08 · 经验避坑库（老板：经验都是好东西，必记必沉淀）

> **规则（老板定，0811）**：每次踩坑/发现好实践，**当场补进本库**（现象 → 根因 → 解法 → 来源）。本库是记忆与排障指南的**结构化沉淀**，改代码/排查问题前先翻一遍。

## A. 环境 / 工程

| 现象 | 根因 | 解法 | 来源 |
|---|---|---|---|
| git push 静默 exit 128（无任何报错） | 执行环境沙箱**拦截 git smart HTTP 协议**出网（curl 直连 github.com 却通 200） | 已由老板默认放行 git 出网——**普通执行直接 `git push` 即可**；gh CLI（走 API 不碰 git 协议）验证仓库最稳 | 0811 实锤 |
| 改 server.py 后"修复没生效" | 旧进程没死干净，服务的是老代码 | 杀全部 server.py 实例（`Get-CimInstance Win32_Process` 按 CommandLine 查，勿信 Get-NetTCPConnection 的 PID 0 假象）→ 确认端口释放 → 起新进程核实新 PID | 多次教训 |
| 8787 访问新端点 404（8777 直连却正常） | 端点没登记 `agnes_proxy.py` 白名单 STUDIO_PREFIXES | **新 /api/* 路由必须同步登记白名单**；曾抓到 faceqc/facefix 漏登记 | 0811 |
| Windows 提交报 `LF will be replaced by CRLF` | Git for Windows 默认行尾转换 | 仓库根 `.gitattributes` 统一 `*.md/*.py/*.js/*.html/*.css/*.json eol=lf`（已加） | 0811 |
| 测试脚本建临时项目报 KeyError `'spec'` | 注册表 projects.json 条目缺 `spec` 字段（load_spec 读 `entry["spec"]`） | 注册表条目必须含 `{"id","name","spec":"{id}/storyboard.json","created"}` | 0811 实测 |

## B. 数据 / 持久化

| 现象 | 根因 | 解法 | 来源 |
|---|---|---|---|
| 新项目需求卡显示旧项目内容 | newProject 未显式清 reqCard / outlineData / visualStyle | newProject 成功后立即清空三件套（不依赖 loadSpec 时序） | 0811 三流程 |
| 新项目需求卡显示旧项目内容（创建后立即有值） | **服务端 `_load_meta` 无 else 分支**：新项目 meta.json 不存在 → 全局 META 保持上一项目残留 → `/api/spec` 返回残留 → 前端 loadSpec 恢复旧值 | `_load_meta` 加 `else: META = {}`（0811 实锤·全流程脚本发现） | 0811 |
| ③场景列表空 / 前端按数组遍历崩 | 分镜模型偶发输出 scenes 为 **dict**（{SC01:{...}}） | load_spec 统一 dict→list 规范化（scenes+props，补 key/name） | 0811 三流程 |

| 测试往真实项目写数据 | 污染生产 meta.json（曾致白屏） | 测试用临时项目，或测后精确恢复；QA 脚本默认走 8787 | 0810 |

## C. AGNES / 生成

| 现象 | 根因 | 解法 | 来源 |
|---|---|---|---|
| 视觉审查用 AGNES 2.5-flash（免费 3000 次/天） | 老板实测对比：输出 5 段结构化+自带瑕疵/质量评估，MiniMax M3 带 think 噪音 | vision_review.py 7 类审查引擎；identity 双图对比能抓服装不一致（实测抓到镜1 白衬衫 vs 深色外套） | 0811 |
| 打开项目后续模块全部不可点 | **loadSpec 无条件覆盖 confirmedSteps**：生成分镜后刷新 spec，内存刚解锁的步骤被服务端旧值（async confirmOutline 与后续操作并发写 ws 产生的竞态中间态）覆盖回锁 | 恢复时**逐位 OR 只进不退**（`confirmedSteps.map((v,i)=> v || !!ws.confirmed_steps[i])`）——闸门只进不退，不再被旧值锁回 | 0811 老板实测 |
| 分镜生成失败"模型未返回 JSON" | AGNES **偶发空响应**（59s 空串）或 thinking 截断致 shots=0 静默生成 0 镜项目 | 重试 3 次，校验条件 = "解析成功**且 shots 非空**"（不只检查 `{}`） | 0811 三流程 |
| 运镜镜头视频无运镜感 | 首帧=角色锚点特写，与提示词"从门口推入"起点矛盾（关键帧与 prompt 打架） | **运镜镜头首帧=运镜起点画面**：场景图/锚点作底图 + `first_frame_prompt` → i2i 生成；源头强制运镜镜头输出首尾帧描述 | 0811 老板洞察 |
| 空镜生成视频画人 | 空镜被判 keyframes + 首尾针缺失 → 文生兜底画人 | 空镜必须 **reference** 策略（场景图单图驱动）；前端 firstFrameUrl 空镜回退显示场景图 | 0810 实战 |
| 本地图片路径传给 AGNES 报错 | AGNES API 只收 **URL 或 data URI**，不收本地路径 | 统一走 `_to_agnes_image()` 转 data URI（_gen_camera_start 曾漏，已修） | 0811 |
| 测试 480p 出片却是 1080×1920 | 合成固定用 storyboard.resolution（模型输出 1080p），无视测试档 | assemble.py 加 `--resolution`，do_assemble 传 `_video_size()`（test 合 480×854 1.9MB） | 0811 三流程 |
| 低分辨率以为省额度 | **额度按时长计，不按分辨率**——480p 只是快/文件小 | 测试用 480p 快速迭代，正式 720p 出片；白天 VIP / 晚上免费 key | 0811 |
| 官方把提交尺寸归一化 | 提交 480x854→448x832，720x1280→704x1280 | 别期待精确尺寸，按档位看待输出 | 0811 |
| 情绪中文"疲惫孤寂"混进英文 prompt | emotion 字段中文直接拼进语音段 | 后端 `_emotion_en` + 前端 emotionEn 翻译表（40+ 词，未匹配→expressive） | 0811 |
| HTTP 524 | CF 等 100s 源站无响应，同步长请求必然触发 | 已改**提交+轮询**（accepted → status）；若再出现说明还有同步请求没改造 | 0810 |
| HTTP 429 | 视频批量超 RPM=5 限流 | 后端自动退避重试（15/30/45s×3）；免费 key 限速排队属正常 | 0810 |
| 视频生成中报 'spec' 异常 | 偶发 KeyError（上下文缺 SPEC 加载） | 确认项目注册表完整、load_spec 成功后再触发 | 0811 |

## D. 前端 / 浏览器

| 现象 | 根因 | 解法 | 来源 |
|---|---|---|---|
| 页面白屏（服务端 200） | Vue 运行时错误；**v-cloak 会让初始化失败时全页隐藏→纯白屏** | 换 `vendor/vue.global.dev.js` 拿详细报错；取 `#app.__vue_app__._container._vnode.component.render.toString()` 定位；④/⑤ 渲染别依赖可能缺失的数组字段 | 0810 实战 |
