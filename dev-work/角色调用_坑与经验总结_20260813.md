# 角色调用 · 坑与经验总结（2026-08-13 实战沉淀）

> 主理人（阿编）整理｜基于 2026-08-13 全天实战：子 agent 通道诊断（探针 AB/C 对照实验）→ 团队模式首战（T-02）→ 常驻班底重建（T-05~T-08）→ 并行派活 + 独立验收闭环。
> 配套制度：`dev-work/角色战队模式·改进与运营手册.md` §3.6（十层防御）+ 反模式清单（14 条）。

## 一、核心结论（先记住这三条）

| # | 结论 | 一句话 |
|---|---|---|
| 1 | **派活必须走团队模式** | Agent 工具直接派发 = 子 agent 根本不启动（无进程/无文件/无返回）；TeamCreate + teammate = 正常执行 + 自动回报 |
| 2 | **回报永远不是真相** | 子角色说"完成"≠完成；主理人必须读盘核验（artifact 存在+非空+git diff 对+真跑 PASS）才算数 |
| 3 | **1 个常驻班底团队跨任务复用** | 不每个任务新建团队（面板堆幽灵成员）；会话结束自动清理，不需要每次删除 |

## 二、踩过的坑（按类别）

### A. 派发通道坑（最严重）

| 坑 | 现象 | 实证 | 处置 |
|---|---|---|---|
| **A1 用 Agent 工具直接派发（非团队）** | 子 agent **静默空返回**：不启动、无文件、无进程 | 探针 A（general-purpose）+ 探针 B（software-engineer）双静默；`probe_a_result.txt` 不存在、无残留进程 | **禁用**，派活必须 `TeamCreate` + teammate |
| **A2 把"调度=自己干"当错觉** | 之前几次"调度=自己干"，实际是走错通道导致没派出去，主理人兜底 = 串行+多绕一圈 | T-04 回退、测试验收均静默 → 主会话接管 | 团队模式通道好使后，"真并行+上下文隔离+自动回报"价值立现 |

### B. 团队管理坑

| 坑 | 现象 | 处置 |
|---|---|---|
| **B1 每个任务/实验都 TeamCreate 新建团队** | 前台面板堆"非原本角色"幽灵成员（probe-diag→probe-c、shortdrama-t02→dev-t02） | 只建 1 个常驻班底 `software-shortdrama`（lead+开发+测试），探针/诊断不建团 |
| **B2 手动 `rm -rf` 删团队目录** | UI 面板不跟磁盘同步，删了盘上文件前台还显示，白删还误导 | 删除用 `TeamDelete`（系统级）；会话结束自动清理，**不需要每次删** |
| **B3 忘了清理历史团队** | 旧 session 遗留的团队实例变成"僵尸记录"在面板堆人 | 任务闭环后优雅 shutdown + TeamDelete；建团前先 `ls ~/.workbuddy/teams/` |
| **B4 会话重载后团队绑定丢失** | 团队目录还在但当前会话无活动绑定（T-08 派活时 "No active team found"） | 重建同名团队（系统自动改名 `software-shortdrama-6e6c`），功能不受影响 |

### C. 信任与验证坑

| 坑 | 现象 | 处置 |
|---|---|---|
| **C1 盲信开发自测输出** | 开发自测"全绿"但主理人独立实跑抓出 P0 缺陷（S1P0 脏双进程） | 主理人必须独立读盘/实跑，不采信文本 claim |
| **C2 把子角色回报当真相源** | 子角色说"完成"但 artifact 空/缺/旧 = 假完成 | 判定矩阵：查 artifact 存在+非空+mtime 新+git diff 对+真跑 PASS |
| **C3 回报消息丢失** | 成员写完文档但没回报（T-05 design/test 已产出 18:13，回报消息没到） | 读盘核验发现已产出 → 直接审阅，不干等消息 |
| **C4 开发异常退出后不读 traceback 就报"完成"** | 假完成（根因=派活 prompt 漏"自修复闭环"约束） | 派活 prompt 必须含「自修复闭环：报错→读 traceback→自己修→重跑→达标才收工」 |

### D. 流程坑

| 坑 | 现象 | 处置 |
|---|---|---|
| **D1 外部方案/卡不审视直接做** | T-07 PRD 没写出的坑 K1（`/ext/status` 在途过滤 `!= 'done'`，迁移中文后恒真→在途统计爆表） | 主理人是最终负责人，外部给的东西先审视（坑/闭环/要不要做）再动手 |
| **D2 测试分层一刀切** | 全部任务都上真视频 = 烧额度；全部 dry-run = 首次打通没证明 | L0 纯逻辑免真视频 / L1 免费 KEY 最小化（1 镜）/ L2 商用完整成片 |
| **D3 成员直连沟通** | 开发直接找测试要结果 → 上下文割裂、交付不可追溯 | 所有跨成员信息流**必须经主理人中转**（单点汇流 + 检查闸） |

## 三、正确姿势（最佳实践）

### 1. 派活通道（铁律）
```
TeamCreate（建常驻班底，会话开始时一次）
  → Agent 派 teammate（team_name + name + 产物契约 + 自修复闭环 + max_turns）
  → teammate 干活并 SendMessage 自动回报
  → 主理人 judge_and_log 读盘判定 → 入台账
  → 收尾 shutdown + TeamDelete（或留给会话自动清理）
```

### 2. 新流程（老板 2026-08-13 定 · 文档先行）
```
需求 → 开发先写 design.md + 测试先写 test.md（并行）
     → 主理人双审（对照 PRD AC 锚点查缺口/越界）
     → 审过才实现 → 主理人核产 + 线上验证（危险操作主会话做）
     → QA 独立验收（fresh eyes，不轻信开发自测）
     → 判定台账 → 完成
```

### 3. 验收判定矩阵（子角色回来怎么判）
| 子角色说什么 | 主会话查到什么 | 判定 | 动作 |
|---|---|---|---|
| "完成" | artifact 存在非空 + git diff 对 + 真跑 PASS | 真完成 | 勾验收 → 完成 |
| "完成" | artifact 空/缺/旧 | 假完成 | 打回，不替写码 |
| "在跑/后台" | 无 task_id 或查无此任务 | 假跑 | 打回 |
| 静默空返回 | 无残留进程、artifact 未动 | 未完成(静默) | 主会话接管实证 |

### 4. 分工边界（架构铁律）
- **子角色只做**：写码 + commit（秒级确定性、无外网等待）
- **永远主会话做**：真跑 / 外网 / 长时验证 / 线上迁移 / 端口重启 / 危险类
- 例：T-07 线上 board.db 迁移（备份→迁移→重启）主理人亲手做；T-08 纯前端改动子角色写完，主理人验证零重启生效

## 五、一句话纪律清单（已固化）

1. 派活必须团队模式，禁用 Agent 工具直接派
2. 回报≠真相，主理人读盘核验（artifact + git diff + 真跑）
3. 1 个常驻班底跨任务复用，不每个任务建团
4. 删除团队用 TeamDelete，不手动 rm -rf
5. 文档先行（design/test 双文档）→ 主理人双审 → 才实现
6. 危险/线上/长时操作永远主会话，子角色只写码+commit
7. 测试分层：L0 免真视频 / L1 免费 KEY 最小化 / L2 商用完整
8. 外部方案先审视（坑/闭环/要不要做），主理人是最终负责人
9. 成员不直连，信息流经主理人中转
10. 长任务每分钟报平安（后台安抚铁律）
