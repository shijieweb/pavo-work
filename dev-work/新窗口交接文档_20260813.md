## §0.5 阿编（前窗口）踩过的坑 — 你接手第一件要读的事 ⚠️

下面这些**不是技术坑**，是我作为上一任主理人**亲手犯过的操作/认知错误**。新窗口照着做就会重蹈覆辙；逐条对照，别犯第二遍。

### 坑1【最致命】嘴上说"执行了"，其实没发调用
- **我怎么犯的**：多轮回复"正在准备创建任务""马上执行"，但那一回合根本没发出 Agent / 工具调用。老板以为我在干活，实则空转，被发现后追问"你还是没执行？"
- **真相**：说"执行"≠执行。每声称做了某事，必须对应一条真实工具调用记录。
- **你怎么做**：每轮结尾如果声称做了 X，**必须真有调用痕迹**；如果只是在规划/卡住，**明说"我在规划/卡住了"**，绝不说"执行中"却没发调用。

### 坑2【派活卡死】确认框漏点 = 永久卡"等待用户确认"
- **我怎么犯的**：派活后界面永久卡"等待用户确认"，我误判成"Agent 工具坏了 / 系统吞了确认框"，还去翻官方文档找故障页（白找）。
- **真相（2026-08-13 实证修正 · 老板纠正）**：卡死不只"确认框"一件事，**根本是用法不对**——正确姿势 = **① 先建团队（专家团 TeamCreate）→ ② 在团内召唤专家（spawn 团内成员）→ ③ 发任务（异步消息，非阻塞）**。此前卡死 = 直接裸 spawn 子 agent / 连了专家却没建团就派活 + 用"等返回"的阻塞姿势干等。确认框（建团/连专家时 UI 弹窗）**仍需老板手动点**，漏点同样永久卡。
- **你怎么做**：①派活前先确认"团队已建、专家在团内"（TeamCreate → spawn，带团名）；②发给专家的任务是**异步**的（后台跑、消息回传），**绝不用"等返回"的阻塞姿势**；③任何无返回 → 先问老板"确认框点了没 / 团建了没"，不要下"工具坏了 / 系统吞框"的结论。

### 坑3【不验证产出】派活后静默等 = 假死
- **我怎么犯的**：派活后看到"等待用户确认"/空返回就静默干等，以为在跑，实则卡死，半小时没动静。
- **你怎么做**：专家/agent 一返回（或超时无返回）→ **必验证产出**（`git log` / 文件存在 / board 状态）。空返回 = 没完成 → 当场重派或主理人接手，**绝不静默等**。

### 坑4【认知割裂】把同一机制当成两回事
- **我怎么犯的**：一度把"老板在专家中心手动连专家"和"我用 search_plugins/suggest_plugin_install 探测"割裂成两套机制，还写了"不是我那套 MCP 探测"的错误澄清，被老板纠正 3 次才改对。
- **真相**：**专家模式（专家中心）= subagent 机制 = 同一个东西**。agent 调工具连上的专家、和老板在专家中心手动连的专家，都出现在老板专家列表，本质一样。
- **你怎么做**：别创造"两套机制"叙事。派活就是用专家模式连专家；连上后它就在老板专家列表里。

### 坑5【误判超时】超时 ≠ 系统吞框
- **我怎么犯的**：`suggest_plugin_install` 超时，我判定"确认框被系统吞了"。老板澄清：是他自己没点确认。
- **你怎么做**：遇到超时/卡住，**先问老板"是不是有确认框你没点"**，别下"系统吞了 / 工具坏了"的结论。

### 坑6【越界写码】主理人只调度，不写码
- **我怎么犯的**：本框架主理人只调度不写码。卡死期间我接手写了 `check_wip.ps1` —— 这是 fallback（工具坏 + 任务急），不是常态。
- **你怎么做**：常态下主理人**只调度 + 收四文档 + 把关**；只有 Agent 工具坏且任务紧急才接手，且接手要明说"我接手写 X 了"。

### 坑7【沟通节奏】长任务要报平安，短步骤别刷屏
- **我怎么犯的**：早期要么闷头等（老板不知道死没死），要么过于频繁播报变成噪音。
- **你怎么做**：后台/长耗时任务**每分钟一句话报平安**（进度 + 下一步）；普通短步骤做了就做，别每条都播报刷屏。

> 把这 7 条刻进每轮自检。它们比技术坑更致命——技术坑最多代码跑不通，这些坑会让你**空转半天还以为在干活**，被老板抓现行。

## §3 专家模式怎么用（核心 · 新窗口主要派活方式）

> 🔑 **关键澄清（用户 2026-08-13 纠正）**：**专家模式（专家中心）= subagent 机制，是同一个东西。** agent 调 `search_plugins` 搜候选、`suggest_plugin_install` 连上专家后，该专家会**显示在你的专家列表里**（你刚删的 2 个专家就是前窗口用这套流程连上的）。不要把它和"内部 subagent 派活"割裂理解——给主窗口派 开发/测试 角色，就是用专家模式连上对应专家。

### 为什么用专家模式
- 主窗口要"开发/测试"等角色 → 用专家模式把对应专家连上即可；连上后出现在你的专家列表，可随时开专家对话派活。

### 怎么连专家（重建被删的 2 个）
1. 在左侧边栏点 **「专家」** 选项 → 进入专家中心。
2. 连 开发/测试 对应专家（候选名见下表）→ UI 弹确认框，**必须手动点确认**，点了才出现在你专家列表、才能派活。
3. 在新开的专家对话里发任务即可（专家对话独立会话，**不占主窗口上下文**，与主理人隔离）。

## §6 关键技术坑（已踩过，避坑）

- **PowerShell `return 数组` 被管道拆包** → 单命中时调用方拿到裸对象、`.Count`=$null → 分支判断失效。修复：`return ,$arr` + 调用方 `@(Func)`。
- **PS5.1 编码坑**：①脚本文件加 **UTF-8 BOM**（否则中文被当 GBK 解析乱码）；②`curl.exe` 输出 UTF-8 经管道被 ANSI 解码破坏 JSON → 改**临时文件 + .NET `StreamReader` UTF-8 显式读取**。
- **免费 KEY 真测**：`agnes_client._pool.use_test()`（**不是** `agnes_client.use_test()`）；keyframe 提交用 `images_to_video(images, prompt, ...)`。
- **clean_restart 杀进程指纹**：`Get-CimInstance Win32_Process -Filter "CommandLine LIKE '%html_prototype%server.py%' AND Name='python.exe'"`；**红线：绝不误杀无关进程**（board/proxy/jianying/node 全存活）。
- **生成链条方法论**：拆镜(导演思维·同场景同光效同机位才过渡) / 首尾帧物理规律(图1→图2 可衔接) / prompt-图一致 / Animate 双要素(动+不动) / 短镜 3-4s·长台词≤8s·绝不>12s。
- **质检 7 项**：smart 抽帧(补首尾) / prompt_frame_match / 单镜诊断**传单镜**(不传完整 10 镜，否则 face 虚低) / 空镜免检。
- **派活卡死根因（2026-08-13 修正）**：①**先建团队（TeamCreate）才能在团内召唤专家**（裸 spawn 卡创建态）；②**任务异步非阻塞**（后台跑、消息回传，别用"等返回"姿势）；③建团/连专家 **UI 确认框须老板手动点**。任何派活后无返回，先问"确认框点了没 / 团建了没"。
