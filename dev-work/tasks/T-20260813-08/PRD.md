## 背景

分析师三界面体检结论：门户最优、看板功能全但有 3 处友好度硬伤（P0）。T-07 已把状态中文化（5 态+阻塞），本卡解决剩余 3 处交互/视觉硬伤。

## 需求（AC）

### AC-1.1 详情入口显式化（P0-1）
- 现状：卡片单击=展开子任务；看详情要**双击（桌面）/长按（手机）**，无任何提示，引导倒置。
- 目标：任务卡片提供**显式「详情」入口**，一眼可见、点击直达详情。
- **方案二选一（design 定，推荐 A）**：
  - A（推荐）：卡片加显式「详情」按钮，点击=查看详情；现有"单击展开/双击详情"行为**保持不动**（改动最小、不破坏现有交互、手机桌面都可用）。
  - B：桌面单击=详情、展开改点箭头（交互重构，改动大，不推荐）。
- 验收：桌面上能明确看到"详情"按钮并点击打开详情；现有展开/收起/双击行为不回归。

### AC-1.2 顶部进度概览（P0-2）
- 现状：只有任务树，一眼看不出"几个进行中/几个完成"。
- 目标：看板顶部加进度概览条：`X 进行中 · Y 待验证 · Z 已完成 / 总数`（5 态中文口径：进行中/待验证/已完成；阻塞/待办/其他单列或并入计数由 design 定，须与任务树实际状态**逐条一致**）。
- 验收：进度条数字与任务树状态分布完全一致（QA 用 sqlite 或 API 交叉核对）；随任务状态切换实时更新。

### AC-1.3 删除按钮弱化（P0-3）
- 现状：红色大字"删除此任务及子任务"紧挨保存，误触风险高（已有 confirm 但视觉太强）。
- 目标：删除入口**视觉降级**为次级样式（ghost/danger 小字），或移到底部单独一行；**确认逻辑必须保留**（不能去掉二次确认）。
- 验收：删除按钮视觉明显弱于保存按钮；点击仍弹确认；确认后删除行为正常。

### AC-1.4 回归红线
- 现有功能零破坏：任务展开/收起、状态切换、保存、新建、5 态中文显示、阻塞态、操作日志均正常。
- `/ext/*` 与后端接口零改动（本卡纯前端）。
