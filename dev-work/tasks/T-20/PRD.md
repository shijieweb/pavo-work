## 四、边界与禁止项

- 不改：外网路由结构、令牌机制、生产数据（训练/出片资产）。
- 禁止：L0 阶段烧 VIP；动 `current_state.md` 以外的验收四文档逻辑；把"新增功能"伪装成 bug 修复绕过闸1。
- 已知坑（主理人提示，开发必须处理）：
  1. **双系统根治是关键**：之前 current_state.md 手工维护 live status 是漂移根因，sync 脚本必须真跑、且主理人 SOP 改为"状态只改 board"。
  2. **"进行中"恒为 0 是表象**：根因是没人把在途任务写进 board；重构后 agent SOP 强制每步 PUT 状态 + sync 脚本兜底。
  3. **blockedBy 是堵塞可视的基础**：没依赖字段就只能源于 status=阻塞，覆盖不全，必须加字段。
  4. **8788 与 8787/board 同步**：前端改动经 8787 反代也要 200 不裂，改完净重启核实。
  5. **禁止直写 SQLite（关键）**：服务单线程 + 无 WAL，任何 agent 直接 `sqlite3.connect(board.db)` 写会与服务抢锁 → `database is locked` 甚至库损坏。统一走 `board_client.py` → API，绝不直连 db 文件。
  6. **看板只存状态、不存遥测**：高频心跳/日志流禁止灌进看板 API（开销隐患唯一来源）；心跳/日志仍走本地文件与既有心跳通道。
  7. **文档库不存 blob 进 SQLite（关键）**：文件落 `shared_board/docs/` 磁盘目录，DB `docs` 表只存元数据（文件名/大小/mime/sha256/路径），**绝不把文件二进制写进数据库**（防 SQLite 膨胀 + 单线程抢锁）；下载走流式文件读，不读 db blob。
