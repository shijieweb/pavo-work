# T-20260813-03 · PRD · 对外入口安全复盘与令牌闸

> 主理人（合伙人）自签闸1并落地（老板 2026-08-13 授权"你干吧"）。
> 四文档分离：PRD / design / test / acceptance。

## 0. 背景（事实，非猜测）
- `agnes_proxy.py:696` 绑定 `0.0.0.0:8787`（全网卡监听）。
- 公网隧道 `agnes.owen1.de5.net` 可达 8787（实测 `GET /studio → 200`、`GET /api/projects → 200` 返回项目数据）。
- `/studio` 全路由 + `do_PUT`(`/api/spec` 等) **无鉴权** → 公网任意人可：①读全部项目源码/meta（IP 泄露）②PUT 改写 `meta.json`/删除项目（文件写破坏）。
- 原 D4"鉴权不做"前提 = "本地网络"；现公网隧道已使该前提**破产**（发现于 2026-08-13 分析师体检）。

## 1. 目标
在不破坏老板日常可达性的前提下，阻断公网未授权读/写 8787 的敏感面。

## 2. 推荐方案 + 理由（老板定调：问题必带推荐+理由）
**推荐：在 8787 代理层加 `PORTAL_TOKEN` 令牌闸（覆盖 /studio 全路由 + /api/* 写面 + /v1·/agnesapi·/console 转发），而非仅把监听改 127.0.0.1。**

- **闭环性两问**：
  1. *能否完成闭环（不断点）*：令牌闸保留隧道可达（老板仍从 agnes.owen1.de5.net 进），仅加一道 token 校验 → 不断老板访问链路；而"绑 127.0.0.1"会直接掐断隧道转发（隧道通常转发到 localhost，但部分隧道实现需服务监听 0.0.0.0），有断点风险，故不选。
  2. *哪个最有效*：令牌闸以最低成本（~20 行 + 一个 env）同时堵"读源码"与"改文件"两类洞；且 token 存 `~/.workbuddy/.env` 不进代码、可随时轮换。
- **理由总结**：这是"保留可达 + 加 auth"的最小可逆改动，符合工程铁律（git before / 可回滚）；老板书签加 `?token=XXX` 即可，摩擦极低。

## 3. 验收标准（AC）
- AC-1：设 `PORTAL_TOKEN` 后，`GET /studio` 无 token → `401`。
- AC-2：`GET /studio?token=XXX` → `200`（老板可达）。
- AC-3：`PUT /api/spec` 无 token → `401`（阻断公网改文件）。
- AC-4：代理内部健康检查 `127.0.0.1:8777/api/projects` 不受影响（自愈拉起正常）。
- AC-5：重启 8787 后老板带 token 访问全功能正常；无 token 一律 401。
- AC-6：未设 `PORTAL_TOKEN` 时维持原开放行为（本地向后兼容，不误伤）。

## 4. 风险预告（动部署边界）
- 重启 8787 会短暂断开老板当前浏览器会话；恢复需带 token。
- 若 token 丢失：重新生成并写回 `~/.workbuddy/.env`、重启即可。
- 缓解：token 明文交付老板 + 提供带 token 的书签 URL；回滚=删 env 行 + 重启。
