# 战队运行手册 · v4（AI 自动驱动 · 双 worker 稳型）

> **视角声明（本手册写给谁看）**：本手册是 **AI 编排者（阿编）的自动驱动协议**，不是「人协作手册」。
>
> - **阿编（我）** = 中枢自动编排器：读板 → 派活 → 校验纪律 → 终验，全程不靠「自觉」，靠流程内置的强制步骤。
> - **老板（你）** = **外部审批者，不进板操作**。只在三道人闸（闸1/2/3）出现确认；其余时间看板对你只是「只读进度 + 审批触发」。
> - **研发 / 测试 worker** = 阿编按需拉起的 AI 手，被派活才醒、干完即休眠；互不聊天，只碰板 + 文档。  
>   核心：文档驱动解耦 + **AI 自动驱动 + 结构强制 + 证据闭环**。纪律写成「阿编派活前必执行的校验」，不是「阿编应该守的规矩」。

---

## 1. 角色与拓扑

| 角色        | 谁        | 定位                  | 职责                                                   | 定义方式                                   |
| --------- | -------- | ------------------- | ---------------------------------------------------- | -------------------------------------- |
| 老板（你）     | 真人       | **外部审批者**（不进板操作）    | 定需求方向、拍板三道人闸                                         | 需求源 + 最终闸门；板对你=只读+审批触发                 |
| 阿编（我）     | 主智能体     | **中枢自动编排器**         | 写需求文档(兼PM)、**按强制协议派活**、校验纪律、终验逐条对照                   | 身份固化于 SOUL/IDENTITY/USER.md + 系统编排工具   |
| 研发 worker | 子智能体     | **被拉起的 AI 手**       | UI设计 + 前端 + 后端 + 自测，产出代码 + 设计/UI文档 + 提测说明 + **证据回写** | Agent 工具拉起，prompt 写明职责 + 工具权限 + 只读共享文档 |
| 测试 worker | 子智能体（独立） | **被拉起的 AI 手（独立视角）** | 按文档写用例 + 独立验证 + 回归 + **证据回写**                        | Agent 工具拉起，只读共享文档，不读研发对话               |

- **拓扑**：编排者（阿编）+ 双 worker（研发 / 测试），中心化，深度 2 层。**阿编是唯一持久决策者，worker 无状态、随叫随到。**
- **单一事实源**：共享文档库，所有 worker 只读文档，不靠对话对齐；**状态外置于看板，阿编每会话重拉，不靠对话记忆。**
- **角色降维**：PM/UI/前/后/测试在 v4 不是独立 agent，而是 worker 的 prompt 职责标签，由阿编派活时指定侧重。
- **信任来源**：纪律不依赖角色自觉——靠 **结构强制（blockedBy/权限边界）+ 证据外置（动作副产物可复核）+ 独立验证（测试验研发、你验阿编）** 三件套。

## 2. 三道人闸（HITL，仅这几处卡你）

| 闸         | 触发           | 说明                                       |
| --------- | ------------ | ---------------------------------------- |
| 闸1 需求基线   | 动工前          | 需求文档你签字才可动（签前阿编逐条复述验收标准，你逐条认可）           |
| 闸2 变更闸    | 任何需求 / UI 改动 | 按「大 / 小阈值」判定：大改动你确认；小改动自动过。agent 禁止擅自改需求 |
| 闸3 UI 最终稿 | UI 文档/稿完成    | 你确认最终稿才可让研发照做                            |

> **闸2「大 / 小」判定阈值**（消除模糊，免扯皮；由原闸2 / 闸4 合并而来）：满足任一 = 大改动（卡你）——①新增 ≥1 个完整用户故事；②预估工作量 ≥2 人天；③涉及对外接口 / 数据模型 / 鉴权变更。**其余**（文案 / 样式微调 / 局部 bug 修复 / 内部重构）一律小改动，自动过不卡你。
>
> **判定信任（不靠阿编自觉，靠结构）**：
>
> - **白名单硬卡**：凡涉及「对外接口 / 数据模型 / 鉴权」三类（即阈值③），阿编**无裁量权**，直接判大、卡你确认，不得自由心证放过。
> - **裁量类必须留痕**：边界模糊的判定（如"局部重构算小？"），阿编判后必须在 `[闸]` 卡 detail 写「判定依据：命中阈值X / 归于小改类目Y」，可复核。
> - **你随时推翻**：闸2 你可见阿编判定 + 依据，认为错判直接推翻、改为卡你确认。阿编判定不是终局，**你才是终局**。
>
> 研发、自测、逐条验收——阿编 + 测试 worker 自动跑，不卡老板。

## 4. 需求文档规则（阿编写，你签）＋ 需求写作工作流

> 文档**格式与字段**见《战队文档格式规范·v1》§1（权威）。本节只定流程与出口。

**需求写作工作流（co-write loop，B 模式「结果稳」）**

1. 老板投喂：原始需求 / 想法 / 规定（可零散、不成熟）
2. 阿编调研：补技术可行性、竞品 / 最佳实践、风险、术语统一 → 出调研摘要
3. 阿编成稿：套格式规范模板，写出含可度量验收标准的初稿
4. 老板 review + 反馈（可多轮）
5. 阿编修订
6. **签基线前强制**：阿编用大白话**逐条复述每条验收标准** → 老板逐条说「这条我认可」→ 才进闸 1 签字；任一条不懂 / 不认可 → 退回步骤 3，**不得带疑签字**

**怎么算通过（完成）**

- [ ] 你签字（闸1）
- [ ] **每条验收标准老板已逐条确认认可**（B 模式铁律，不可跳过）
- [ ] 验收标准可度量、无歧义、覆盖所有功能点
- [ ] 每条验收标准可被下游文档追溯

## 5. 研发设计文档规则（研发写，阿编审）　格式详见《战队文档格式规范·v1》§2

**包含什么**

- 技术方案 / 模块划分 / 数据结构
- **API 接口契约**：路径 + 方法 + 入参/出参 schema + 错误码 + 鉴权 + 版本
- 依赖 / 风险 / 自测计划
- **提测说明**（关键！）：本地启动命令、环境变量、服务端口、测试入口、测试数据准备、已知限制

**怎么算研发完成（DoD）**

- [ ] 代码合入主干（draft PR 经本机 CI gate 过 + 阿编审）
- [ ] 自测全过，产出**自测报告（含证据A）**：① `git diff` 改动文件清单 ②本机跑测试的命令 + **真实 stdout 输出**（如 `12 passed`）③关键页面**运行截图**
- [ ] 无未解决 blocker
- [ ] 需求/设计/UI/测试四文档已更新（改动回写）
- [ ] 提测说明可被测试 worker 照做启动（阿编本机验证命令/依赖/端口/数据齐）

**自测怎么自测（自测规范 · 证据A粒度）**

- 单元测试覆盖核心逻辑与边界
- 接口自测按「接口契约」逐字段核对出入参与错误码
- UI 自测按 UI 文档逐页面对照（含空态/异常态）
- **证据回写（轻量但必须真跑）**：自测不是「我说测过了」，而是贴出**动作副产物**——命令 + 真实输出 + 截图。阿编验证证据后才推进 `[研发]` 卡，不靠口头声明。
- **证据可复现铁律（2026-08-12 吸收 board-less 模式优点）**：**无输出 = 未测 = 不通过**；凡声称「完成」必须附可重跑的动作副产物（命令 + 真实 stdout + 截图），**测试通过 = 唯一完成标准**，口头声明 /「我测过了」一律不算数。

## 6. 测试文档规则（测试写，阿编勾）　格式详见《战队文档格式规范·v1》§3

**包含什么**

- 测试用例：前置条件 / 步骤 / 预期 / 优先级（对照需求验收项编号）
- 覆盖矩阵：每行需求验收项 ↔ 对应测试用例（证明全覆盖）
- 回归点：历史缺陷回归清单
- 集成测试点：跨模块/跨接口接缝
- 自测证据复核：研发自测报告核对结论

**怎么算通过（完成 · 证据A）**

- [ ] 用例 100% 覆盖需求验收项（覆盖矩阵闭环）
- [ ] 研发自测证据复核通过（命令输出 + 截图可重跑）
- [ ] 独立验证关键路径通过（测试亲自跑，非研发自报）
- [ ] 无 P0 / P1 未决 bug
- [ ] 阿编持验收对照表逐条勾完，**每条勾后附证据链接**（哪次输出/哪张截图证明这条过）
- [ ] **证据可复现铁律生效**：勾「通过」必须附可重跑证据（命令+输出+截图）；无证据=未测=不通过；**测试通过=唯一完成标准**（非阿编/研发自报）

**bug 单格式（测试提交 · 必带证据）**  
`编号 / 模块 / 现象 / 复现步骤 / 期望 / 实际 / 环境 / 严重度(S1-S4，测试定，写 title [Sx]) / 业务优先级(P0-P3，阿编定，写 title [Px]) / 验收项锚点(AC-xxx，写 title) / **截图或日志（必带）** / 提交人`

**回流闭环（结构强制分离）**：测试提单（定严重度+截图）→ 阿编定优先级 → 研发修 → 测试回归（重跑+截图）→ 关闭。**全走文档/任务卡，不卡老板；分离职责由阿编权限边界强制**：研发只推 `待验证`，**无 `done` 权限**，只有测试验过、阿编才 `done`——不是靠研发自觉。

## 8. 我补充的其他规则（衔接缺口补丁）

1. **文档互审 gate（交叉校验）**：测试写用例时反向校验研发设计文档的接口是否可测——接口写不清则写不出用例，自然暴露设计缺陷；阿编把「文档互审」当派活后的一道 gate。
2. **验收对照表**：阿编终验用，= 需求文档验收标准的**结构化提取**。研发/测试完成佐证后，阿编逐条勾，不靠感觉。
3. **反馈分流**：你提的修改分两类——**缺陷**走 bug 流（不卡你，测试回归）；**新需求**走变更闸（闸2，你确认）。
4. **变更控制**：需求/UI 大改 → 你确认（闸2 变更闸）→ 阿编重定基线 → 广播 → **文档回写**（DoD 硬条件，防 spec debt）。
5. **回归触发**：每次变更合入后，测试 worker 跑回归点清单。
6. **单一事实源铁律**：所有 worker 只读共享文档，不靠对话对齐；改动必须回写文档，否则不算完成。
7. **弱项后门**：研发 worker 卡壳时，阿编可临时调专家 agent 补位（默认关，不增常驻角色）。
8. **防失联 + 证据可复现（2026-08-12 吸收 board-less 模式优点）**：worker 回报 开始/完成/阻塞 + 长任务 10 分钟心跳（见 §9.1）；任何「完成」须附可重跑证据，无输出=未测=不通过。阿编据此不靠记忆掌握进度与真伪。

## 9. 全流程四阶段

```
需求写作 → 研发(UI先出稿) → 测试 → 反馈
   │            │               │         │
 闸1          闸3(UI稿)       自测+独立   变更/确认
 你签         你确认          验证(不卡你) 你提反馈
```

- **需求写作**：阿编兼 PM 写 PRD（走 §4 co-write 工作流，签基线前逐条复述验收标准给你确认）→ 你签基线（闸1）
- **研发**：先出 UI 稿 → 你确认（闸3）→ 写设计文档 + 前后端 + 自测 + 提测说明
- **测试**：按测试文档写用例 + 独立验证 + 回归；bug 走回流闭环
- **反馈**：你直接对验收对照表提反馈；缺陷走 bug 流，新需求走变更闸

## 9.1 阿编派活强制协议（AI 自动驱动核心）

> 本手册的「自动驱动」不是口号——它落地为阿编**每次派活前必须顺序执行的强制校验**。任一步不过，派活卡住，不靠自觉。

**派活前校验链（顺序执行）**：

1. **读板重建状态**：每会话先拉看板 + 文档锚（PRD/acceptance），不靠对话记忆（N-loop）。
2. **闸态校验**：下游卡若 `blocked` 于某 `[闸]` 卡，且闸未 `done` → **禁止派活**，先解决闸。
3. **WIP 校验**：目标 worker 进行中卡数达上限（研发≤2 / 测试≤2 / bug修复≤3）→ **禁止拉新**，先清在制品。
4. **编码解析**：从目标卡 `title` 解析类型前缀 + `[Sx|Px]` + `AC-x.y`，缺关键编码 → 退回补，不派。
5. **证据复核**：上游卡若宣称完成，必须已回写**证据**（命令输出/截图/文档），无证据 → 不推进。
6. **派活**：给 worker 的是「文档路径 + AC 编号 + 证据要求」，不内联需求全文。
7. **设 blocked / 写日志**：新卡 `parent_id` 绑定前置，操作记审计日志（谁/何时/动作）。

**推进校验链（worker 回写后）**：

- 研发推 `待验证` → 阿编验证据 → 派测试。
- 测试推 `已验证` → 阿编验证据 → 才 `done`（bug 分离职责）。
  - 终验：对照表逐条勾，**每条附证据链接** → 才报你收货。

**worker 回报纪律（防失联，2026-08-12 吸收 board-less 模式优点）**：研发 / 测试被派活后**必须回报 开始 / 完成 / 阻塞 三节点**；长任务每 10 分钟一次**心跳**；完成**自动通知**阿编。禁止「闷头跑完再回来」——阿编靠回报实时掌握进度，不靠猜、不靠记忆。

## 10. 各角色 DoD（完成定义）

- **研发 DoD**：合入(本机CI过) + 自测过(证据A:命令输出+截图) + 无 blocker + 四文档已更新 + 提测说明可启动
- **测试 DoD**：覆盖矩阵闭环 + 独立验证过(亲自跑) + 无 P0/P1 + 对照表佐证齐全(每条附证据)
- **阿编 DoD**：逐条过验收对照表(每条附证据链接) + 终验报告(截图/输出) + 文档归档
- **老板 DoD**：人闸处（闸1/2/3）确认——**你只在这三处出现，其余只读**

## 11. 防翻车铁律（4 条核心，由 8 条去重合并）

1. **文档即唯一事实源 + 证据外置**：只读共享文档不靠对话对齐；下游通过条件回溯需求验收项（验收可追溯）；每次变更必回写文档否则不算完成。**证据 ≠ 角色声明，而是动作副产物**（命令输出 / diff / 截图），可打开、可重跑、可复核。**（证据可复现铁律：无输出=未测=不通过；测试通过=唯一完成标准）**
2. **结构强制（不靠自觉）**：纪律写成「阿编派活前必执行的校验」（闸态 / WIP / 编码解析 / 设 blocked），不执行则派活卡住；bug 分离职责由阿编权限边界强制（研发无 done 权）；闸卡 blocker 保证你不被跳过。
3. **独立验证**：研发自测交**证据报告** + 测试独立验证(亲自跑) + 文档互审（测试写用例反向校验设计接口可测性）+ B 模式逐条确认（签基线前阿编逐条复述、老板逐条认可）。
4. **兜底与升级**：失败护栏（每循环 max_hops≤5、卡死 / 超限保存状态干净升级，绝不靠 LLM 自判完成）+ 弱项后门（研发卡壳阿编临时调专家，默认关）。
5. **安全铁律**：禁提交密钥 / 硬编码；AI 代码过安全扫描；auth / 支付 / 权限类改动需人审，不自动合；worker 最小权限。

## 12. 代码仓库与 git 工作流（P0，跑得起来的地基）

> 没有这一节，研发 DoD「合入主干」是悬空承诺——第一轮试跑就会卡在「代码交不出去」。

- **单一仓库结构**：`<workspace>/projects/<需求ID>/src/`（代码）、`/docs/`（四份文档：PRD/design/ui/test/acceptance）、`/roles/`（角色记忆）、`.env.example`（密钥模板，真实 `.env` 入 `.gitignore` 永不上库）。每个需求实例独立子目录，与看板 `[需求ID]` 前缀一一对应。
- **分支模型 = trunk-based**：`main` 是只读圣源，worker **绝不直推 main**；只在短生命周期 feature / fix 分支工作
- **分支命名**：`feat/<任务ID>-<简述>`、`fix/<任务ID>-<简述>`（任务 ID 来自共享看板）
- **提交纪律**：每个子任务一个**原子提交**，message 含任务 ID + 验收项编号（如 `#23 AC-F2.1 登录失败提示`）——agent 发疯时好回滚
- **合入规则**：worker 只提 **draft PR**，绝不直合；PR 经 **CI（测试 + lint + 安全扫描）通过 + 阿编审** 后才合入 main
- **CI 才是真老板**：每 PR 自动跑测试 / lint / 安全扫描；CI 不过则 PR 不合并（确定性闸门，不靠人记）
- 研发 DoD「代码合入主干」= 上述 PR 经 CI + 阿编审核合入 main

## 13. 失败兜底与硬性上限（P0，跑不崩的护栏）

> 我们的 co-write / 研发 / 验收都是循环。没有上限，agent 一旦钻牛角尖互相 ping-pong，烧的是真钱（业界有 $180/20 分钟、$47000/11 天的真实案例）。

- **每循环 max_hops ≤ 5**：co-write、研发、验收任一循环超过 5 轮无结论 → **转人工升级**，不靠 LLM 自判「完成」
- **重试退避**：失败重试最多 3 次，指数退避（1m → 5m → 15m），避免死循环
- **全局护栏**：单任务 token 预算 / 时间预算设上限；超限 → **保存当前状态**（进度 + 决策点）干净交接，升级给老板
- **卡死判定**：连续 N 轮无实质进展 → 触发护栏，附「已完成 / 卡在哪 / 需要你拍板的决策点」升级
- **确定性编排**：阿编的「终止 / 跳转 / 升级」由规则定，不由 LLM 自由决定（接 §14 升级协议）
- **升级协议**：任何未决议题必须明确「升级对象 + 时限」，禁止静默卡死

## 14. 安全与密钥（P1，商用级必备）

- **禁提交密钥 / 硬编码**：仓库只留 `.env.example` 模板，真实密钥入 `.gitignore`；密钥不入文档库 / 角色记忆 / 对话
- **AI 代码过安全扫描**：每 PR 跑安全扫描（依赖漏洞 / SQL 注入 / 鉴权缺陷 / 敏感信息泄露）
- **敏感改动人审**：auth / 支付 / 权限 / 数据模型类改动，需阿编（或老板）人审，不自动合入
- **最小权限**：worker 工具权限按职责最小化授予，研发不拿生产密钥，测试不拿写库权限
