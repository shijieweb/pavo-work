## 一、为什么乱 / 看板"没用上"的病灶（已查实）

**结构乱**：一个 git 仓库 `WorkBuddy/workbuddy` 同时塞了 3 套东西——生产引擎 + 训练线（训练线还在另一个**无 git** 目录 `projects/short-drama-training/`）+ 协作运维，根目录还堆了十几份手册 md。

**看板"没用上"三大根因**（不是没建，是建歪了）：

1. **方向错位**：8788 现状标题是「任务看板」，本质是**阿编内部开发任务追踪器**（X-Agent 头 / owner 路由 / 写锁全是给 agent 用的）。老板要看的是"我的短剧生意进展到哪了"，它给不出。
2. **双系统漂移**：真实进度在 `dev-work/current_state.md`（阿编认真维护），看板喂得不一致 → 实测 22 任务里 **0 个"进行中"、12 待办 / 10 完成**，老板一打开像死数据，更不会去看。
3. **T-08b 整块没落地**：筛选 / 状态快切 / 指导留言 / 自动刷新 / 完成时间戳全没做（08-13、08-14 已写两份方案却没执行），交互别扭。

## 四、看板优化方案（重点）

### 核心判断
8788 必须从「开发任务看板」**重构为「老板业务指挥台」**——它现在喂的是开发 task list，老板要的是业务进度 + 实时信号。

### 4 步改造
1. **消灭双系统漂移（最优先）**：`current_state.md` 的"在途任务"自动同步成看板"进行中"（解析 md → 写 board，定时任务或阿编收工触发）。看板成为**唯一进度真相**，不再 0 进行中。
2. **新增老板首页「业务总览」**：剧本/分镜数、出片集数、训练批次/采纳配方数、流水线健康、当前瓶颈。一眼看全局，而非开发任务卡。
3. **补齐 T-08b 交互**：状态/优先级筛选、卡片状态快切、指导留言栏、自动刷新、完成时间戳。
4. **清理垃圾项目**：删「测试项目 / 看板项目」测试残留，建真实 3 工作线项目（生产 / 训练 / 运维）。

### 验收锚点
- 老板打开 8788 首页 = **业务总览**（非开发 task list）
- 看板"进行中"实时反映 `current_state.md` 在途任务（不再恒为 0）
- 筛选 / 快切 / 留言 / 自动刷新可用；测试残留项目已清
