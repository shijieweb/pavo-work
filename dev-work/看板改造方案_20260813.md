### 2.7 接入固化与规则强制（老板 18:45 问：本地成员怎么固化？外部角色怎么被告知规则？）
- **参与者 × 通道 × 固化方式**：
  | 参与者 | 通道 | 固化方式 |
  |---|---|---|
  | 主理人（我） | 8788 API + `X-Agent` + `X-Board-Token` | board 技能 SKILL.md（已有） |
  | 本地团队成员（开发/测试） | **代理模式**：产出交主理人统一落板（子 agent 静默风险，不直连） | 派活 prompt 附规则摘要 + 主理人代理 |
  | 远程指导角色（外部机器） | 8787 `/ext/*`（无鉴权） | `GET /ext/spec` 自描述契约 + 接入规范文档 |
  | 老板（浏览器） | 网页 UI | index.html（无感） |
- **机制一（首选 · 老板 18:48 定）· 网页 API 说明页**：board 加 `GET /docs`（人类友好 HTML 页）——本地 `8788/docs`，外部经 8787 可达（`/board/docs` 或 `/ext/docs`）。页面内容：状态/优先级枚举（中文）+ 端点表 + 必带字段 + curl 示例（本地带 `X-Agent` / 外部 `/ext` 免鉴权）+ 身份与写锁规则。**外部角色打开网页即知全部规则，零门槛、最直观**。
- **机制一备选（机器契约 · 后置可选）**：`GET /api/spec`（JSON 自描述）——等真有"机器消费方"（外部自动化脚本）时再做，不做纯文档重复。
- **机制二 · 服务端校验强制**：POST/PUT 任务校验：title 非空、priority ∈ {紧急/高/中/低}、status ∈ 5 态枚举；非法 → **400**。
  - **为什么加（老板 18:51 问）**：不是防"坏人"，是防"脏数据"——手滑/脚本 bug/角色理解偏差都会产脏数据（board 现状就是英文 todo/doing 与中文混着，2.6 才要迁移）；校验让规则成为**系统边界**而非文档建议——**没有校验，2.6 迁移完还会再脏**；且 board 数据是 check_wip/前端//ext 的共同输入，脏数据会传导。成本仅几行代码（枚举集合+非空判断）。
- **配套**：说明页即"接入规范"载体（内容内嵌页面，不另造 md 重复文档）。
- **验收锚点**：`GET /docs`（本地 + 外部路径）可达且内容完整（枚举/端点/示例/规则）；POST 非法 status / 缺 title → 400。

### 2.5 注册表热加载（老板 18:20 提议 · 并入看板 v2 外部 API 任务）
- **现状**：route_registry.json 已落地（T-02 已实现 `_load_route_registry()`），但仅**进程启动读一次** → 改注册表（加服务/改前缀）仍需重启 8787。
- **方案**：改为 **mtime 惰性重载**——照抄项目现有 `_BOARD_TOKEN_CACHE` 先例：每请求 stat `route_registry.json` 的 mtime，变化才重载（缓存秒级）。效果：**改注册表 = 零重启、秒级生效**，覆盖"加服务/改路由"90% 场景。
- **边界**：前缀冲突校验保留（新注册表冲突 → 拒绝加载、沿用旧路由）；热加载只覆盖**声明式路由变更**；代码逻辑变更仍走干净重启（工程铁律）。
- **价值**：8787 是老板唯一入口，可用性大幅提升；与 2.3 状态机扩展无冲突。
