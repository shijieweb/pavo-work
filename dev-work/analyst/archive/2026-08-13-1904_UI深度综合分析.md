# 分析师留言 #6 · UI 深度综合分析（使用角度 + 视觉角度）

- **投递时间**：2026-08-13 19:04 ｜ 分析师
- **优先级**：研究结论（补充 #5；供 UI 改进排期）

## 一、使用角度（Usability）
| 界面 | 细节 | 问题 | 级别 |
|---|---|---|---|
| 看板 | 长按 vs 点击冲突 | 手机长按=详情、点击=展开，500ms 判定，手指不稳易误触 | P1 |
| 看板 | 保存成功无反馈 | 只有失败 alert，成功静默——用户不确定存没存上 | P1 |
| 看板 | 无搜索 | 任务树只能肉眼扫，任务上百后是刚需 | P1 |
| 看板 | 自动刷新 5s | 重渲染整棵树（drawer 输入不丢，可接受）；手机端持续轮询略耗 | P2 |
| 门户 | 一键启动超时静默 | 轮询 30s 后 catch 忽略，用户不知道"没起来/没超时" | P1 |
| 门户 | 离线点"看当前成片"静默 | preventDefault 但无提示 | P2 |
| 工作台 | 批量生成逐镜状态可见性 | 生成/成功/失败/返工需明确 per-shot 状态色（建议渲染确认） | P1 |

## 二、视觉角度（Visual Design）
| 界面 | 细节 | 问题 | 级别 |
|---|---|---|---|
| 看板 | **主题割裂** | 看板亮色白底 vs 门户暗色——从门户进看板暗→亮视觉断裂 | **P0** |
| 看板 | 优先级"中"=灰色 | #f3f4f6 on #fff 对比弱，层级看不出 | P1 |
| 看板 | 新态徽章颜色未规划 | T-07 新增"待验证/已验证"：建议待验证=amber、已验证=purple（与 T-07 同批定） | P1 |
| 门户 | 卡片层级失衡 | 调试台/工作台双列小卡，看板/日志/训练营全宽大卡——**老板常用的工作台+看板权重不够**，建议前置双列 | P1 |
| 门户 | 入口布局不对称 | 2 双列 + 3 全宽，视觉权重混乱 | P1 |
| 看板 | header 控件拥挤 | 6 个控件小屏换行堆叠 | P2 |

## 三、结论与排期建议
1. **最有价值仍是 #5 的三处 P0**（详情入口/进度概览/删除弱化）。
2. 本轮新重点：**视觉 P0=看板亮暗主题割裂**（加暗色或统一）；**使用 P1=保存成功无反馈 + 启动超时静默**（"做了没结果"最伤体验）。
3. **T-07 联动**：新增"待验证/已验证"徽章配色**在 T-07 同批规划**（待验证=amber、已验证=purple），别等状态改完再补色。
4. 排期：T-07 同批=#5 三处 P0 + 新态配色 + （可选）看板暗色；P1（搜索/筛选/toast/启动超时提示/卡片层级）开后续小卡；P2 累积。
