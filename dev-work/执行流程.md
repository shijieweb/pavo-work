> 不靠记忆、不临场自创、不裸用 Agent。本文件是唯一调度入口；
> 所有可复用动作已下沉为 skill / 脚本（见末尾速查表），优先调已固化资产。

## 第 0 步：先读本文件
接任务的第一动作 = `Read dev-work/执行流程.md`。没读就不动手。

## 第 1 步：判定任务类型
- **A 类 · 团队调度**（写代码 / QA / 需多人协作的调研）→ 走第 2 步
- **B 类 · 本地执行**（git 推送 / 清僵尸进程 / 跑脚本 / 只读核查）→ 直接调速查表对应 skill/脚本，**不建团队**

## 第 2 步：团队调度（仅 A 类，走 software-team-dispatch 技能）
1. 查 `~/.workbuddy/teams/`：在则复用，不在则 `TeamCreate`（名 `software-board`）
2. `Agent` 带 `team_name` 拉 `software-engineer` + `software-qa-engineer`（禁裸 Agent / 禁把 TeamCreate 塞进 Agent）
3. `SendMessage` 派活（写清任务 + 只读/可写边界）
4. `Read` 团队 `config.json` 核验**真入队**（§4.3，防静默空返回）
5. 队友回报后，**主理人亲自读盘核产**（跑命令拿真 stdout），不拿"完成"当证据（I-5 铁律）

## 第 3 步：固化（每次任务的尾巴）
任何可复用流程 → 写成 skill 落 `~/.workbuddy/skills/` 或脚本落 `short_drama_workflow/scripts/`。

## 第 4 步：翻大白话
结果压成「表格 + 要点」，给老板一句话结论 + 待办选项。
