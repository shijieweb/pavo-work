## 3. 双角色闭环的实证价值（为什么必须有"测试独立验收"）

> 本框架最贵的设计 = **开发推待验证即停（无 done 权）+ 测试独立验收（不修 bug）** 的两道分离。下列真实案例证明它值。

### 3.1 BUG-1（S1 P0）：开发自测全绿，测试+主理人抓出脏双进程
- T-20260812-03 开发自述 `clean_restart_studio.ps1` "全绿、0 缺漏"提交。
- 主理人独立实跑：单残留稳态下脚本**谎报"无残留"→ 跳过杀进程 → 反派生重复进程**，留下脚本本要杜绝的**脏双进程**（BASELINE 21120 → 又冒出 17712，POST `studio PIDs: 21120, 17712`）。
- **根因**：PowerShell 函数 `return $array` 被**管道枚举拆包**，单命中时调用方拿到裸 `CimInstance`，`.Count` 为 `$null` → `$null -gt 0` 恒 False → 跳过杀分支。
- **修复**：`return ,$out` + 调用方 `@(...)`。主理人重跑复验：BASELINE 29716 → 精确杀除 → 重拉 3188 → 单一健康（`OLD killed=True`/`EXACTLY ONE=True`），board/proxy/jianying/node **0 误杀**。

### 3.2 实测 > 推断（重要方法论）
- 我的隔离探针一度误判"单命中 Count=1 正常"——因为探针在**本地变量**查 `.Count`，没经函数 return 拆包。直接实跑才暴露。→ **推断不如实测，永远用真实行为验证，不靠逻辑推理**。

### 3.3 证据不信任：测试 Agent 写文件失败 → 主理人接手
- 本轮测试 Agent 写 `test.md`/`current_state.md` 时工具反复报错（content 丢失 4 次），只给出口头结论。
- 主理人按"证据不信任"原则**接手亲自实跑 + 落文件**，不依赖其文件产出。→ 后续遇 Agent 写文件异常，主理人应直接接手实证与落文件。

### 3.4 双角色还抓过什么
- T-20260812-01（P0-1 YAML 化）：开发 116 项回归"全绿"，测试独立复验抓出 2 个生产级 BUG（empty_scene text:/i2i: 语义丢失、camera_move assets/ data_uri 丢失）——回归 fixture 用 `/fixture` 路径掩盖了 `assets/` 分支。

### 3.5 自修复闭环缺失 → 假完成（T-20260813-01 l1_smoke 实证）
- 开发写完 `l1_smoke.py` 后报"完成"，但 `run.log` 实际在 `import server` 直接 `ModuleNotFoundError` Traceback 退出——真测没跑、成片没出、`last_url.txt` 没生成、`design.md` §3 证据仍是占位符。系统通知"completed"只是它 agent 回合结束，**非任务真成**。
- **根因**：主理人派活 prompt 只写"跑通后回报"，**漏了"自修复闭环 + 达标才收工"约束** → 开发崩了不读 traceback、不重跑、不修、直接回报。这是坑3（不验产出）+ 坑7（不报平安）的双重失守，本质是**派活提示词约束缺口**。
- **修复（本任务起强制执行）**：
  - **派活模板必含「自修复闭环纪律」**：任何非 `exit(3)` 守卫拒绝的异常退出，必须自己读 traceback → 定位 → 修复 → 重跑，循环到真跑通为止；达标（真出片 + 证据落盘 + git commit 交付物）才回报完成；**禁止中途退出、禁止谎报"在跑/完成"**。
  - **主理人核产三招判真假完成**：①`last_url.txt` 出没出（PASS 才写）②`tail run.log` 看真排队还是已 Traceback ③`tasklist|grep python` 看进程在不在。三样不达标 = 假完成，打回重做。
  - 开发角色若崩后只报"完成"不自愈，主理人直接打回并补派活约束，不替它写码（主理人铁律：不碰代码）。

### 3.6 外部可观测性铁律：子角色永非真相源（测试静默空返回 实证）
- **两轮坑的共同根因**：§3.5 开发的"假完成" + 本轮测试的"静默空返回（连 test.md 都没写、无挂死进程）"——**本质都是把"子角色自己回报的状态"当成了真相源**。失败的那一方，恰恰是最该回报失败、却没回报的一方 → 逻辑死结。
- **铁律（本任务起强制执行）**：子角色的"完成 / PASS / 在跑 / 后台"一律**不算数**；真相只在磁盘上，由**主会话自己读**。
- **七层防御（保证"任何错都瞒不过你 + 不造成不可逆伤害"；注意：不是保证"子角色不犯错"——后者物理上不可能，且不需要）**：
  1. **真相外置（坑3 升级）**：主理人独立读盘——`run.log` / `test.md` / `git diff` / 成片 URL / 命令 exit code；子角色的文本 claim 一律不采信。
  2. **硬边界防卡死**：Agent 派活必带 `max_turns`（硬回合上限）；`TaskOutput` 必带 `timeout`（绝不 `block` 永久）；真跑命令包 `timeout`(coreutils) / `--max-time`(curl)。**超时即判失败，绝不静等**。
  3. **产物契约（把"成没成"变成磁盘布尔）**：每任务强制落一个 artifact 路径；主理人查 `exists + size>0 + mtime 新`。空/旧/缺 = 未完成，无视子角色说什么。
  4. **心跳倒置**：主理人轮询，不靠子角色自报（坑7 反向应用）。长真测放主会话可控后台，主理人拿 `<task-notification>`，随时 `TaskOutput`。
  5. **回收闸**：超时不归 → `TaskStop` 该 task_id + 主会话接管重跑；子进程遗弃，不陪等。
  6. **架构铁律（已立）**：子角色只写码+commit（秒级确定性、无外网等待）；**真跑 / 外网 / 长时验证 永远主会话**。危险类不委派，从根消类。
  7. **派活契约升级**：prompt 必含 产物路径 + 期望 exit code + 自修复闭环（§3.5）+ 结构化回报格式（命令 / exit / artifact / AC 逐条）。无 artifact = 未完成。
- **判定矩阵（子角色回来后主理人怎么判）**：
  | 子角色说什么 | 主会话查到什么 | 判定 | 动作 |
  |---|---|---|---|
  | "完成" | artifact 存在非空 + git diff 对 + 真跑 PASS | 真完成 | 勾验收 → 完成 |
  | "完成" | artifact 空/缺/旧 | 假完成 | 打回，不替写码 |
  | "在跑/后台" | 无 task_id 或 TaskOutput 查无此任务 | 假跑 | 打回 |
  | 静默空返回（无文本无文件） | `tasklist` 无残留、artifact 未动 | 未完成(静默) | 主会话接管实证 |
  | 卡死 | TaskOutput `timeout` 超、无 notification | 卡死 | TaskStop + 主会话接管 |
  | 崩（traceback） | 读 traceback | 异常退出 | 令其自修复到真跑通，否则打回 |
- **诚实边界（100% 能保证什么）**：无法保证子角色产出"好"、不浪费额度；但能 **100% 保证**——①瞒不过（真相在盘，主会话读）②不烧 VIP（`mode` 守卫 `exit 3` 前置）③不误杀常驻（PID 指纹排除，见 §4.2）④不卡死（`max_turns` + `TaskOutput timeout` 双硬边界）。

## 4. 技术坑库（可复用 · 复制即用）

### 4.1 PowerShell 函数 `return 数组` 被管道拆包 ★
- **规律**：函数 `return $arr` 会被管道枚举拆包；单元素时调用方 `$x = Func` 拿到**裸标量**，`$x.Count` 为 `$null`（PS5.1）。任何 `$x.Count -gt 0` 分支会恒 False。
- **修复范式**：①函数内 `return ,$arr`（逗号包裹强制单元素数组）②调用方 `$x = @(Func)` 双重保险。
- **诊断**：隔离探针在本地变量查 `.Count` 会误判正常；必须在"经函数 return 拆包后的调用方上下文"验证，或直接实跑。

### 4.2 clean_restart 杀进程：精确指纹 + 排除
- 用 `Get-CimInstance Win32_Process -Filter "CommandLine LIKE '%html_prototype%server.py%' AND Name='python.exe'"`（主指纹加 `Name='python.exe'`，避免误中命令行提及该路径的无关进程如 powershell 探针自身）。
- `MatchExtra` 排除 `shared_board`/`agnes_proxy`，防误杀 jianying 等其它 python server。
- **禁用 `Get-NetTCPConnection`** 查 8777 残留——它常把端口归 PID 0（假象），真查残留用 `Get-CimInstance Win32_Process` 按 CommandLine 匹配。

### 4.3 免费 KEY 切换：函数名别写错
- 正确：`agnes_client._pool.use_test()`（切到 test 模式）。
- **错误**：模块级 `agnes_client.use_test()`（不存在，会 AttributeError）。已写入守则 G0-5 / I-2 两处更正。
- `AGNES_TEST_API_KEY` 无限额度、仅排队（可接受），不占 VIP。

### 4.4 单镜诊断传单镜，不传完整 10 镜
- `/api/diagnose` 单镜诊断必须传**单镜** storyboard（`{shots:[{id,duration}]}`）。传完整 10 镜会让抽帧点挤开头 → 人脸误检 intra_jump → face 虚低。

### 4.5 商业化镜头生成链条（已固化 server.py）
- **拆镜（导演思维）**：单镜内同场景/同光效/同机位；差异大→拆多镜链式衔接。
- **首尾帧物理规律**：图1→图2 必须物理可衔接（空镜=文生图 no people + NEG；人物镜=i2i 强约束景别"占 60-70%"才真走近）。
- **prompt-图一致**：prompt 描述必须与首尾帧实际差异吻合，图和文矛盾 AI 只按图生成。
- **Animate 双要素**：Animate(动)+Keep stable(不动) 必填；reference 缺 Animate 会定格。
- **时长匹配**：短镜 3-4s、长台词≤8s、绝不>12s。

## 5. "做少=忘少"自动化路线（O4 提前排期）

> 老板拍板：真正自动才是王道。本次把 O4 从"O5 再说"提前。

### 5.1 现状痛点
状态活在阿编脑子 + 手改 markdown → 失忆/翻车根因（免费KEY 忘真测、current_state 自填完成不验证、fork v4 漏强制项）。

### 5.2 board 技能已确认能力（机械强制，非自觉）
调研 `board` 技能（`~/.workbuddy/skills/board/SKILL.md`）确认：
- **服务端写锁（硬约束）**：写接口须带 `X-Agent`；服务端只允许改 `owner==自己` 的项目，改别人返回 **403** → agent 即便幻觉也物理改不了他人项目。
- **审计日志（自动写）**：agent 每次写操作服务端记一条（谁/何时/动作/目标），老板在「操作日志」可见。**R2 审计由系统机械写，不需阿编手改 md。**
- **online 状态**：每次拉板自动记"最后访问时间"，老板看谁在线。
- **parent_id 层级**：支持项目→主任务→子任务（部分 blockedBy 能力）。

### 5.3 待补（O4 迁移计划，子任务卡另开）
- **WIP 限制**：board 无内置并发上限。方案：GATE0 调 board API 查 `doing` 任务数，超 研发≤2/测试≤1/bug≤3 则拦截。可写成 `ops/check_wip.ps1` 小脚本。
- **blockedBy 强制**：用 `parent_id` + GATE0 校验"父 blocked 则子不动"。
- **迁移**：`current_state.md` 任务状态 → board 项目任务树；markdown 审计段降为兜底（O4 启用后系统自动写）。

### 5.4 结论
O4 不是"再加一个角色"，而是**把状态机/审计/WIP 从阿编自觉变系统强制**——这才是"做少=忘少"的真杠杆。角色层面维持 主理人+开发+测试 三角色即可。

## 6. 运营 runbook（每日 / 每次派活）

### 6.1 启动 SOP（新会话第一件事，顺序 Read）
1. `主理人守则.md`（不变量 + GATE0）
2. `运行手册.md`（流程结构）
3. `current_state.md`（看板 + 操作审计段）
4. `.workbuddy/memory/YYYY-MM-DD.md`（今日日志）

### 6.2 派活前 GATE0 十二项（逐条勾，缺一不可）
G0-1 四文档就位 · G0-2 AC 锚点 · G0-3 模板化 · G0-4 触生成必 L1 · G0-5 KEY 用对 · G0-6 自主边界 · G0-7 证据铁律 · G0-8 心跳 · G0-9 before 快照 · G0-10 收尾记忆 · **G0-11 自签留痕+白名单** · **G0-12 WIP 检查**。

### 6.3 状态推进纪律
- 开发：推「待验证」即停，无 done 权。
- 测试：推「已验证」即停，不修 bug，提单交回开发。
- 主理人：只有「已验证」才标「完成」，对照验收表逐条勾证据。
- **每次推进 → 在 `current_state.md` 操作审计段追加一行**（O4 启用后系统自动写）。

### 6.4 心跳（老板铁律，不松）
被派活立即回「开始」；卡住回「阻塞+原因」；长任务（>10min/含排队）每 10 分钟心跳；阿编对老板**每分钟一句话报平安**；干完回「完成」+自动通知。

## 7. 反模式清单（千万别做）

7. ❌ 加新角色来解决"阿编失忆" → 只增协调面，应改自动化（见 §5/§8）。
8. ❌ 改动 server.py/agnes_proxy.py 业务逻辑来"修"流程问题 → 流程问题改守则/手册/O4。

## 8. 角色决策记录（本次：不加新角色）

**问题**：老板问"需要给你加一个角色吗？" 
**决定**：**不加。** 分析（闭环 + 有效）：
- 闭环：dev/test 已覆盖写码/验码；剪辑·成片·运维已脚本化无需角色。缺口不在"活没人干"，在"阿编手动记状态"。
- 有效：加新角色 = 多一个协调面（派活+等回报+核产出）→ 阿编做更多，与"做少=忘少"背道而驰。
- 真杠杆：O4 board 机械闸门（自动审计+owner写锁），比再派一个 agent 盯阿编更稳。

**唯一可能有益的"监察"角色**被 O4 机械闸门替代（系统自动写审计 > agent 看阿编）。维持 主理人+开发+测试 三角色。
